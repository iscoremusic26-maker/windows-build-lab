# CP10.6B — implementation and evidence (Dusklight 40457c6)

## 1. Resource
- `ID_AK_JN_WINDLINE00 = 0x046` (`include/d/d_particle_name.h` L90; file `AK_JN_windLine00.jpa`, `src/d/d_particle_name.cpp` L109). IDs without the 0x8000 bit are the **common** bank (bank 0, loaded at boot); `dPa_RM(id) = 0x8000 | id` selects the scene bank, so **0x0046 and 0x8046 are different resources** (`d_particle_name.h` L8). The code asserts `kResource == 0x0046`, bit 0x8000 clear, bank 0.
- The source never spawns it by name, so nothing is known about its look from the engine code. Existence of the symbol is not availability: `aura_probe()` looks the resource up in `pResMgrAry[0]->getResource(0x0046)` before the first `set()` (the engine's `set()` reads the resource's user work before checking that it exists) and logs `DEVF_CP10_6B_WINDLINE event=RESOURCE_PROBE ok=0 reason=...` if it is missing; on success it logs the **scalar metadata** of the loaded resource once (user work, dynamics flags, volume type/size, max frame, start frame, life, rate, velocity, emitter direction, shape type/direction/rotation type, base size, colour-animation type, base prm/env colours, key/field/texture counts, child/extra shape presence). All getters are header inlines; no new import (the import set is exactly CP10.6A's).

## 2. Emitter lifecycle (read from `d_particle.cpp`, `JPAEmitter.cpp`)
- `dComIfGp_particle_set(key, id, &pos, &tevStr, ...)` -> `dPa_control_c::set(u32 key, ...)`: with a live `key` of the same name it refreshes (`onActive`, `playCalcEmitter`, `setGlobalTranslation(pos)`, restarts emission if it was stopped); otherwise it creates one through `createSimpleEmitterID` and registers it as an **immortal level emitter** (`level_c::entry`). `dComIfGp_particle_getEmitter(key)` returns it. We keep only the `u32` key.
- **NULL returns** of the creating `set()` (L1468-1560): resource manager missing, **`tevStr->Material_use_fg != 0x7C`**, or `createSimpleEmitterID` failing (pool exhausted / group unavailable). `RealEngine::ready()` checks the tevStr first; `windline_policy.hpp` turns each refusal into a bounded retry (see 4).
- **Cleanup is native:** `level_c::execute` cuts every level emitter that was not refreshed during the frame (`!isActive()`, L971-984; `cleanup()` L937-955 invalidates it). We call `stopDrawParticle()` when the fade-out completes, and stop refreshing; a dead actor, a room change or an unload also just stops refreshing. During a cutscene the engine pauses instead of cutting (`isEventMove()`), so a cutscene cannot leave a stuck emitter either. Keys are unique and monotonic: a stale key never resolves to a newer emitter. **No emitter of anybody else is ever touched** (only our own key is looked up).
- **Finite effects:** `JPABaseEmitter::processTermination` (JPAEmitter.cpp L103-128): after `mMaxFrame` ticks emission stops (`status 8`) and a non-immortal emitter ends. If the probe reports `max_frame != 0`, a newly created emitter gets `becomeContinuousParticle()` (`mMaxFrame = 0`) so the lines keep being produced while the buff lasts. This only changes our own emitter instance; the shared resource is not modified.
- **Colour and alpha:** per emitter `setGlobalPrmColor / setGlobalEnvColor / setGlobalAlpha / setGlobalScale` after each `set()` (as `d_a_kytag03.cpp` does every frame). The draw code multiplies the particle colour by `mGlobalPrmClr` / `mGlobalEnvClr` and its alpha by `mGlobalPrmClr.a` (`JPABaseShape.cpp` L25-37, `JPARegist*`), so a tint is a multiplication of whatever colour the resource animates: a pale/white stroke takes it, a coloured one is mixed. After configuring, the global prm colour is **read back** and logged (`COLOR_APPLIED` if it matches, `COLOR_UNAVAILABLE` if not). That proves the engine holds the value we set; it does **not** prove the on-screen colour. The resource's own base colours are in the `RESOURCE_PROBE` line to interpret the first result.
- Alpha: the CP10.6A caps (110 / 130) are boosted x1.8 (198 / 234) because strokes are thin; one table (`windline_policy.hpp` `kBlue` / `kBlack`) holds colour, emitter scale (1.5) and boost for the next round.
- Position: the middle of the body (`current.pos` to `eyePos`), refreshed every tick (the keyed `set()` moves the emitter). No rotation is applied in this first candidate; the emitter direction is in the probe line.

## 3. What did not change
Same single `daE_OC_c::execute` hook (one PRE, one POST); CP10.6A fade state machine and ownership model (`devf_vis::step`, unchanged file reused by `#include`), eye pipeline (seven private CMPR variants bound to one Black's eye packet, ownership-checked, restored on fade-out/unload), logic (`group`, `fury`), identity, HP, regeneration, damage, texture, editor, provider. The 4 particle imports of 0.8.1 (`dComIfGp_particle_set`, `dComIfGp_particle_getEmitter`, `JPAResourceManager::getResource`, `dPa_control_c::mEmitterMng`) are exactly the same; the audit's reviewed set is unchanged.

## 4. Transient refusals (`windline_policy.hpp`)
`AuraPart` (over a tiny engine adapter, run identically by the mod and the lab): probe, then `ready()`, then `set()`, then `configure()` (lookup + scale/colour/alpha + readback). Any refusal returns "pending": the logical state stays on (the 6A controller keeps fading), the next tick retries, the first one logs `EMITTER_REJECTED retries=1 reason=...` (transient), a success after retries logs `EMITTER_ACQUIRED`, and after `kRetryTicks = 60` consecutive failures the generation is rejected permanently (`EMITTER_REJECTED` from the controller, no further attempts, no log spam). The retry counter is stamped by actor id + generation: a new generation never inherits it. A handle that expired meanwhile (event, scene change) is recreated exactly once and its colour re-applied. Aura and eye faults are independent: a WindLine failure never touches the eye textures and vice versa.
- Capacity: at most 8 simultaneous aura emitters (explicit, `kMaxEmitters = devf_vis::kMaxAuras`, shown as `emitters_used/emitters_max` in every line); the 9th is rejected cleanly. One emitter per actor in this candidate.

## 4b. Logs (bounded: 24 lines per actor shared with the eye lines, 400 per session, only on transitions)
`DEVF_CP10_6B_WINDLINE event=RESOURCE_PROBE | BLUE_ON | BLUE_OFF | BLACK_ON | BLACK_OFF | EMITTER_REJECTED | EMITTER_ACQUIRED | EMITTER_RELEASED | COLOR_APPLIED | COLOR_UNAVAILABLE`, with actor id, generation, variant, source, encounter, state, level, alpha, resource `0x0046_ID_AK_JN_WINDLINE00`, bank, emitter key, emitters used/max, target rgb, rgb/alpha read back, scale, retries, reason. `DEVF_CP10_6A_VISUAL` keeps the eye lines (`BLACK_EYES_ON/OFF`, `BLACK_VISUAL_REJECTED part=EYES`), `VISUAL_RELEASED` and `VISUAL_CLEANUP`. `BLUE_ON` while the emitter is still being retried carries `reason=LOGIC_STATE_ON_EMITTER_PENDING_RETRY`. The `DEVF_CP10_6_DYNAMIC`, `DEVF_CP10_5_DAMAGE`, `DEVF_CP10_4_VARIANT`, `DEVF_CP10_3_REGEN` and `BLACK_TEXTURE_*` lines are unchanged.

## 6. Not verified
The WindLine's real shape and whether it reads as suspended thin strokes; whether the tint changes its pixels; whether `becomeContinuousParticle()` is needed or harmful for this resource; behaviour in cutscenes; the shared pool under load; other mods hooking `daE_OC_c::execute` or particles.
